Every program so far in this course was written by somebody who knew the rules.
Adding two numbers, routing a packet, normalising a table — in each case a person
worked out what should happen and expressed it.

Some problems resist that. Nobody can write down the rule that distinguishes a
photograph of a cat from a photograph of a dog. You can recognise it instantly and
you cannot say how. The rule exists; it is simply not available for inspection.

**Machine learning** is what you do instead: supply thousands of examples, and
have an algorithm find a rule that fits them.

## What is actually being learned

The essential shift is where the behaviour comes from.

| | Traditional programming | Machine learning |
| --- | --- | --- |
| The programmer supplies | The rules | The examples, and the shape of the model |
| The computer supplies | The output | The rules, and then the output |
| You can read the logic | Yes | Often not |
| Wrong answers are | Bugs, findable in the code | Statistical, reduced but not eliminated |

That last row deserves attention. A conventional program with a bug can be
debugged: there is a line responsible, and it can be corrected. A model that
misclassifies has no such line. Its behaviour lives in thousands or billions of
numbers, none individually meaningful.

<Aside kind="trap" title="Machine learning is not the answer to every problem">
Questions frequently describe a problem for which it is the **wrong** tool, and the
marks are for saying so.

Do not use it when the rules are known and exact. Tax, payroll, password checking,
booking systems — all have rules written down, all require exact answers, and a
model that is 99.7% right is a catastrophe rather than a success.

Do not use it when there is no data, when the data available is unrepresentative,
or when a wrong answer cannot be tolerated and the reason for a decision must be
explainable.

The test to apply: *are the rules knowable and stateable?* If yes, write them.
</Aside>

## The three kinds

<Figure caption="What distinguishes them is what the data arrives with — answers, nothing, or a score after the fact.">
  <LearningTypes />
</Figure>

**Supervised learning.** Every training example comes with the correct answer.
Photographs already labelled cat or dog; emails already marked spam; houses with
their sale prices. The model learns a mapping from input to that known output, and
success is measured by comparing predictions against labels that were held back.

This is the most common kind in practice, and the labels are usually the expensive
part — somebody has to produce them, one at a time.

**Unsupervised learning.** No labels at all. The algorithm is asked to find
structure that nobody specified: which customers behave similarly, which
transactions look unlike all the others.

There is no correct answer to compare against, which means there is no clean way to
tell whether it worked. The groups either turn out to be useful to a person or they
do not.

**Reinforcement learning.** The system acts, and receives a reward or a penalty. It
is never told what it should have done — only how well things went. Over many
attempts it learns which actions tend to lead to reward.

This is how programs learn to play games. It suits problems where the right action
depends on a sequence of moves whose payoff comes much later, which is exactly the
case supervised learning handles badly.

## The vocabulary

A **feature** is one measurable input. For a house: floor area, bedrooms,
postcode, year built. The features are all the model sees — anything not encoded as
a feature might as well not exist.

A **label** is the right answer for a training example. The actual sale price.

A **model** is what training produces: a set of numbers, plus a rule for combining
them with the features to produce an output.

**Training** is the process of adjusting those numbers so the outputs move closer
to the labels.

<Py packages={["numpy"]} caption="A model fitted from data, with nothing hand-coded about the relationship. Step through the loop and watch the error fall.">{`
import numpy as np

# Houses: floor area in square metres, and the price they sold for.
area  = np.array([45, 60, 72, 88, 95, 110, 128, 145, 160, 180], dtype=float)
price = np.array([142, 178, 205, 240, 262, 296, 340, 378, 415, 462], dtype=float)

# The model is two numbers. Nobody has told it what they should be.
slope, intercept = 0.0, 0.0
rate = 0.00002

for step in range(1, 4001):
    predicted = slope * area + intercept
    error = predicted - price
    loss = float(np.mean(error ** 2))

    # Nudge both numbers in the direction that reduces the error.
    slope -= rate * float(np.mean(error * area)) * 2
    intercept -= rate * float(np.mean(error)) * 2

    if step in (1, 10, 100, 1000, 4000):
        print(f"step {step:>5}  loss {loss:>10.2f}  price = {slope:.2f} x area + {intercept:.2f}")

print()
print("the model was never told that price rises with area — it found that")
print()
for a in (75, 130, 200):
    print(f"  {a:>3} m2 -> predicted {slope * a + intercept:6.1f} thousand")

# 200 m2 is beyond anything it was trained on, so that last one is a guess
# about territory it has never seen.
print()
print("largest house in the training data:", int(area.max()), "m2")
`}</Py>

<Aside kind="why" title="Why the last prediction is worth distrusting">
The model above happily prices a 200 m² house, having never seen one above 180 m².
It will produce a number for a 5000 m² house too, and for a house of negative area.

A model has no notion of the limits of its own experience. It has fitted a line and
will extend that line anywhere it is asked. Whether the relationship it found
continues to hold outside the range of the training data is a question about the
world, and the model has no access to the world — only to ten examples.

This is **extrapolation**, and it is one of the most reliable ways for a deployed
model to be confidently wrong. It also generalises: a model trained on one
population, or one season, or one country, is extrapolating whenever it is used
outside those conditions, and it will not say so.
</Aside>

<Takeaway>
Machine learning trades a rule you can read for a rule you could not have written.
That is a good trade when the rule is genuinely unwriteable, and a bad one when
somebody already knows it.
</Takeaway>
