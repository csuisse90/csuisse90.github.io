    a: >-
      A truth table redrawn as a grid, arranged so that adjacent cells differ in exactly one variable. Groups of adjacent $1$s can then be read off as simplified terms.

  - q: >-

    a: >-
      A power of two — $1, 2, 4, 8, 16$ — and rectangular. A group of three or six is not allowed.
  - q: >-

    a: >-
      It removes one more variable. A group of $2^k$ cells eliminates $k$ variables from the term.

Boolean algebra works, but it requires you to spot which law applies. Miss a step
and you get a correct answer that is not the simplest one, with no indication that
anything is wrong.

A **Karnaugh map** replaces insight with looking. Draw the truth table as a grid
laid out in a particular way, and the simplifications become visible as
rectangles.

## The layout, and why it is odd

A two-variable map is a $2\times2$ grid; three variables give $2\times4$; four give
$4\times4$. Each cell holds the output for one input combination.

The unusual part is the ordering of the headings: $00, 01, 11, 10$,
not $00, 01, 10, 11$.

This is **Gray code**, and it is the whole idea. In Gray code, consecutive values
differ in exactly one bit. So any two adjacent cells on the map differ in exactly
one variable — which means combining them eliminates that variable, by
$X\overline{Y} + XY = X$.

If the columns were in ordinary binary order, cells 01 and 10 would sit next to
each other while differing in *two* variables, and adjacency would mean nothing.

## Grouping

Circle rectangles of $1$s. The rules:

1. Every group contains only $1$s (or $1$s and don't-cares).
2. Every group has a size that is a **power of two**: 1, 2, 4, 8, 16. Never 3, 6
   or 12.
3. Groups are rectangular — no L-shapes.
4. Groups may **overlap**, and often should.
5. Groups **wrap around** the edges. The map is a torus: left touches right, top
   touches bottom. On a $4\times4$ map the four corners are mutually adjacent and
   form a valid group of four.
6. Make every group as **large** as possible, then use as **few** groups as
   possible while covering every $1$.

Rule 6 is where marks are won and lost. A group of four eliminates two variables;
two groups of two eliminate one each. Bigger is always better.

<Aside kind="why" title="Why groups must be powers of two">
Combining two adjacent cells works because of
$X\overline{Y} + XY = X(\overline{Y} + Y) = X$ — one variable takes both values
across the group, so it drops out.

A group of four is two groups of two combined, so two variables drop out. A group
of eight is two groups of four, so three drop out. Each doubling removes exactly
one more variable, and $2^k$ cells eliminate $k$ variables.

A group of three cannot be built this way. There is no arrangement of three cells
in which some variable takes every value an equal number of times, so nothing
cancels and there is no term to write. It is not a rule imposed for tidiness; a
group of three does not correspond to any product term.
</Aside>

## Reading a group

Look at which variables stay **constant** across the whole group. Those are the
ones that appear in the term. Any variable that changes has been eliminated.

- Constant at $1$ → appears plain: $A$.
- Constant at $0$ → appears inverted: $\overline{A}$.
- Changes → omitted.

A group of four on a four-variable map leaves two constant variables, so the term
has two literals. A group of eight leaves one. A group of sixteen — the whole map
— leaves none, and the function is simply $1$.

## Don't-care conditions

Some input combinations cannot happen. A circuit reading a binary-coded decimal
digit will never see $1010$ through $1111$, because those are not digits.

Mark those cells $\times$. When grouping, you may treat each one as $0$ or $1$,
independently, whichever produces larger groups. You are not obliged to cover
them.

This is genuinely free simplification, and it is often substantial: a BCD circuit
has six don't-cares out of sixteen cells, which usually collapses the expression
dramatically.

<Aside kind="trap" title="A don't-care is a promise, not a guess">
Marking a cell as don't-care asserts that the input combination **cannot occur**.
If it does occur, the circuit will produce whatever the grouping happened to
imply — which might be anything.

In real hardware this is a genuine hazard. If a sensor can fail in a way that
produces an "impossible" code, the circuit's response is unspecified and could be
dangerous. Safety-critical designs therefore often refuse to use don't-cares at
all, accepting a larger circuit for a defined response to every input.
</Aside>

## Prime implicants

Two terms make the process precise.

A **prime implicant** is a group that cannot be made larger. There is no point
considering smaller groups — they are always worse.

An **essential prime implicant** is a prime implicant that covers at least one $1$
which no other prime implicant covers. That $1$ can only be dealt with by this
group, so it must be in the answer.

The method: find all prime implicants; take every essential one; then, if any $1$s
remain uncovered, choose the fewest remaining prime implicants that cover them.

<Py caption="Quine–McCluskey — what a Karnaugh map does, done algorithmically. This is the method software uses, because it keeps working past the point where a grid cannot be drawn.">{`
from itertools import combinations

def combine(a, b):
    """Merge two terms differing in exactly one position, using - as a wildcard."""
    diff = [i for i in range(len(a)) if a[i] != b[i]]
    if len(diff) != 1:
        return None
    return a[:diff[0]] + "-" + a[diff[0] + 1:]

def prime_implicants(minterms, bits):
    terms = {format(m, f"0{bits}b") for m in minterms}
    primes = set()
    while terms:
        used, nxt = set(), set()
        for a, b in combinations(sorted(terms), 2):
            merged = combine(a, b)
            if merged:
                nxt.add(merged)
                used.add(a)
                used.add(b)
        primes |= terms - used
        terms = nxt
    return sorted(primes)

def as_expression(term, names):
    parts = []
    for ch, name in zip(term, names):
        if ch == "1":
            parts.append(name)
        elif ch == "0":
            parts.append(name + "'")
    return "".join(parts) if parts else "1"

minterms = [0, 1, 2, 5, 6]
names = "ABC"
primes = prime_implicants(minterms, len(names))

print(f"minterms {minterms} over {names}")
for p in primes:
    covers = [m for m in minterms if all(c == "-" or c == format(m, "03b")[i]
                                          for i, c in enumerate(p))]
    print(f"  {p}  ->  {as_expression(p, names):<6} covers {covers}")

# A minterm covered by only one prime implicant makes that implicant essential.
print()
for m in minterms:
    covering = [p for p in primes
                if all(c == "-" or c == format(m, "03b")[i] for i, c in enumerate(p))]
    if len(covering) == 1:
        print(f"  minterm {m} is only covered by {as_expression(covering[0], names)} — essential")

## Where maps run out

Four variables fit comfortably. Five is possible with two stacked $4\times4$ maps,
treating corresponding cells as adjacent, and it is already unpleasant. Six is
beyond reasonable.

The problem is dimensional: adjacency in $n$ variables is adjacency on an
$n$-dimensional cube, and paper has two dimensions. Beyond five the eye cannot see
which cells are neighbours.

Software therefore uses **Quine–McCluskey**, above — the same idea expressed as an
algorithm rather than a picture. It is exactly what a Karnaugh map does: find all
prime implicants by repeatedly merging terms that differ in one bit, then select a
minimal cover. It scales to as many variables as you like, at the cost of being
unusable by hand.

<Takeaway>
A Karnaugh map is a truth table drawn so that "simplifiable" looks like
"rectangular". The Gray code ordering is not decoration — it is the entire
mechanism.
</Takeaway>
