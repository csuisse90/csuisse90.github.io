      The pointer to the first node. Lose the head and the whole list is unreachable.

    a: >-
      The last node's `next` pointer is null, which is what a traversal tests for.

  - q: >-

An array holds its elements together by putting them next to each other. A
**linked list** holds them together by having each one point at the next.

That single change swaps every cost around.

## The node

```python
class Node:
    def __init__(self, value):
        self.value = value
        self.next = None      # the address of the next node, or nothing
```

A list is a chain of these, plus one pointer called the **head** naming the
first. The last node's `next` is null, and that null is how a traversal knows to
stop.

The head deserves respect. It is the only reference into the structure. Overwrite
it before saving what it pointed to and the entire list becomes unreachable — the
memory is still there, and nothing in the program can ever find it again.

## Traversal

Every algorithm on a linked list is a variation of this:

```
current ← head
WHILE current ≠ null
    do something with current.value
    current ← current.next
END WHILE
```

Note what is absent: any index, and any use of a length. You cannot ask for the
tenth node; you can only be at a node and move to the next.

## Insertion, in the right order

Inserting after a node `p`:

```
new.next ← p.next        (1)  copy before you overwrite
p.next   ← new           (2)
```

Do those two lines in the other order and `p.next` now points at the new node
while the new node points at itself or at nothing — and the rest of the list has
no remaining reference. It is gone.

<Aside kind="trap" title="The classic exam mistake, drawn out">
```
p.next   ← new           (1)  WRONG ORDER
new.next ← p.next        (2)
```

After line 1, `p.next` is the new node. Line 2 then reads `p.next`, which is now
the new node, and sets `new.next` to itself.

The result is a list ending in a node pointing at itself. Any traversal loops
forever, and every node that followed `p` is lost.

The rule, and it applies to every rewiring in this topic: **copy the old pointer
out before you write over it.** In exam answers, state the two assignments in
order and say why. That ordering is usually worth a mark on its own.
</Aside>

## Deletion

To remove a node you need the one *before* it, because that is the pointer that
has to change:

```
previous.next ← current.next
```

The node is now bypassed. Nothing points at it, so it is unreachable and its
memory can be recovered.

Two cases need care. Deleting the **head** means moving the head pointer instead.
Deleting from an **empty list** must be refused rather than crashing.

<Aside kind="why" title="Why deletion needs the previous node, and how doubly linked lists escape it">
The pointer that must change lives in the *preceding* node, and a singly linked
node has no way to reach backwards. So the only way to find it is to traverse
from the head keeping a second reference one step behind.

That is why deletion is quoted as $O(n)$ overall despite the rewiring itself
being one assignment: finding the previous node is the expensive part.

A **doubly linked list** stores `prev` as well as `next`, so given any node you
can reach its neighbour on both sides and delete it in genuinely constant time:

```
node.prev.next ← node.next
node.next.prev ← node.prev
```

The price is a second pointer in every node — often as much memory as the data —
and two pointers to keep consistent on every operation instead of one, which is
twice as many chances to get it wrong.
</Aside>

class Node:
    def __init__(self, value):
        self.value = value
        self.next = None

class LinkedList:
    def __init__(self):
        self.head = None

    def show(self):
        parts, node = [], self.head
        while node is not None:
            parts.append(str(node.value))
            node = node.next
        return " -> ".join(parts) + " -> None" if parts else "(empty)"

    def insert_front(self, value):
        node = Node(value)
        node.next = self.head        # copy the old pointer out...
        self.head = node             # ...then overwrite it
        return self

    def insert_after(self, target, value):
        node = self.head
        while node is not None and node.value != target:
            node = node.next
        if node is None:
            return False
        new = Node(value)
        new.next = node.next         # order matters, see above
        node.next = new
        return True

    def delete(self, value):
        previous, current = None, self.head
        while current is not None and current.value != value:
            previous, current = current, current.next
        if current is None:
            return False             # not present
        if previous is None:
            self.head = current.next # deleting the head
        else:
            previous.next = current.next
        return True

    def find(self, value):
        steps, node = 0, self.head
        while node is not None:
            steps += 1
            if node.value == value:
                return steps
            node = node.next
        return None

    def reverse(self):
        previous, current = None, self.head
        while current is not None:
            following = current.next   # save, because the next line destroys it
            current.next = previous    # turn this link round
            previous = current         # shuffle both markers forward
            current = following
        self.head = previous
        return self

items = LinkedList()

    items.insert_front(v)
print("built by inserting at the front:", items.show())

items.insert_after(12, 5)
print("insert 5 after 12             :", items.show())

items.delete(7)
print("delete 7                      :", items.show())

items.delete(12)
print("delete the head               :", items.show())

print()
print("find 9  ->", items.find(9), "steps from the head")
print("find 99 ->", items.find(99), "(not present)")

for v in (20, 30, 40):
    items.insert_front(v)
print()
print("before reversing:", items.show())
print("after reversing :", items.reverse().show())
print()

## Variations

**Doubly linked** — each node also points backwards. Traversal both ways,
constant-time deletion given a node, at the cost of a pointer per node.

**Circular** — the last node points at the first instead of at null. Useful for
anything that cycles: round-robin scheduling, a playlist on repeat. Traversal
must count or watch for the starting node, because there is no null to stop at.

**With a tail pointer** — keeping a second pointer to the last node makes
appending constant time instead of $O(n)$. Almost every real implementation does
this.

## When to use one

Use a linked list when the size is unpredictable and the work is insertion and
removal rather than indexing.

Use an array when you index, when you want to binary search, or when the data is
walked through repeatedly and cache behaviour matters.

The one thing a linked list can never do is jump to the middle — which is why a
sorted linked list cannot be binary searched, even though a sorted array can.

<Takeaway>
A linked list trades instant access for cheap rearrangement. Every operation on
one is a matter of pointer assignments in the correct order, and the correct
order is always: copy the old pointer before overwriting it.
</Takeaway>
